Examiner Viva Defense Guide & GPU Telemetry

1. "Why did you build an NLI verification layer instead of prompting the LLM to verify itself?"
The Examiner Trap: Many students think "Self-Reflection" (asking the LLM "Are you sure?") works.
Your Defense: LLM self-reflection suffers from confirmation bias. If the model had an attention blind spot and extracted a ruled-out condition, prompting it in the same context almost always reproduces the hallucination. Our system uses an orthogonal bidirectional cross-encoder (DeBERTa-v3) specifically trained on natural language inference to re-examine the claim against the source note independently.
2. "How was the decision threshold τ* derived without data leakage?"
Your Defense: We maintained a strict 50/50 partition (20 Dev notes / 20 Test notes) using seed 7. The decision threshold (τ* = 0.3499) was optimized strictly on the Dev split to maximize F1 of accepted chart entries. It was then frozen in policy.json and applied blindly to the Test split. All reported numbers (92.9% precision, 56.2% error capture) are on the held-out Test split.
3. "What is Expected Calibration Error (ECE) and why does it matter?"
Your Defense: Standard accuracy ignores whether stated confidence matches reality. An uncalibrated model can give a lethal wrong dosage with 99% confidence. ECE calculates the gap between predicted confidence and observed empirical accuracy across probability bins. Our test split achieved an ECE of 0.1353.
